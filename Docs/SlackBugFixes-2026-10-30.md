# Slackバグ報告の対応記録（2026-10-30）

対象：#all-t-cardの投稿本文。TSの全44投稿と過去バックログを照合。
現行仕様が後続投稿で変更されているものには、古い要望を再導入しない。

## 今回修正

| 報告された症状 | 原因・対応 |
|---|---|
| 自分のJokerだけ攻撃できない | CardActionIcon.CanAttackがJokerClearBattleArea効果を攻撃不可扱いしていた。通常のCannotAttack等は維持してこの除外を撤去。 |
| Jokerの一掃が自分側にも適用される | 発動元の陣営から相手フィールドを特定して除去。通常・リバース・敵味方を共通化。AIの一掃後の予測も更新。 |
| リバースJokerが自らも墓地へ行く | HandDealerが9とJokerを同じ即時消滅分岐で処理していた。Jokerは場へ残す。追加ターンを選択した場合の専用処理は維持。 |
| Jackが10・7に一方的に勝つ | BreakableJackがアセット名の「Jack」を検索していたが、実アセット名はSpade_J等。ランク11を使い、10・7側の特殊勝利が実戦でも成立するよう修正。Jack自身のBreakableFace仕様は保留。 |
| 相手手札1枚・場6枚目の10の破棄が機能しない | 相手の手札が1枚の場合は唯一の対象をその場で破棄し、選択UIの有無に依存しない処理へ変更。 |
| チャージしないと十分なリソースがあってもプレイできない | ドラッグ中、リソース用CanvasGroupを一律有効にする処理を修正。ポインターが実際のリソース判定内にある場合だけ有効化し、フィールドのドロップを遮らないようにした。 |
| アクトカードが効果中に場へ表示され配置が変わる | プレイヤー・CPU・リバースの効果元を非表示化。BattleAreaLayoutの配置対象とAIの戦闘一覧からスペルを除外。手札中のスペルは手札上限・手札破棄の数に含める。 |
| Aceの選択中に進行／対象なしで停止 | 既存の効果待機を維持。対象が一枚もないAceは選択モードへ入らず解決して墓地へ送る。 |
| Redrawボタンが反応しない／背後を操作できる | 全CanvasGroupの一括書換えを廃止。手札・フィールド・ウォール・リソースのゲーム操作枝のみロック。元の状態を保存・復元し、モーダルのボタンは親の入力ロックに巻き込まれない。演出のRaycastを解除時に有効化しない。 |

## 既存対策を回帰確認

- 通常召喚直後の6の召喚酔い：4スートで攻撃不可。
- 8の防御と生存後レスト：4スートで再ブロック不可。
- 「6がJokerを一方的に倒す」：通常戦闘では6側が墓地へ行く。
- フィールド上限6枚：通常の7枚目を拒否、スペルは配置枚数へ加算しない。
- リソース4・手札4がある第5ターン：自動終了しない。
- Kの軽減が可能な場合：行動ありと判定。
- リソース13のKing/Joker、リソース14の2：追加チャージなしでルール上プレイ可能。
- 第6ターン以降：序盤の行動不能自動スキップの対象外。
- Kingのウォール回復：1回1枚・発動陣営へ回復・累計上限を超えない。
- ウォール幅・高さ：独立設定が既存カードへ反映される。
